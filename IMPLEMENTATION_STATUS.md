# Implementation status

This repository now contains a **bounded, CPU-testable scaffold** for a North DFlash training investigation plus isolated exact-runtime GPU gates. It is not a training recipe and must not be treated as deployment-ready.

## Implemented and tested

- `ResponseExample` dataclass and `schemas/response-example.schema.json` for tokenized, target-generated prompt/response examples.
- Deterministic local-RNG anchor sampling based on DFlash paper §4.2 and §A.1: at most a configured number of distinct full blocks; one clean anchor followed by `block_size - 1` masked futures; no partial tail blocks.
- Dependency-free CPU batch layout for concatenated sampled blocks: flattened labels/loss masks/block IDs, absolute clean anchor positions, exponential position weights, bidirectional within-block query visibility, and frozen target-context visibility strictly before each clean anchor.
- Optional `.[torch]` tensor adapter, isolated in `north_dflash_training.torch_layout`: one packed CPU-neutral `[1, Q]` query batch with int64 IDs/labels/positions, bool loss mask, floating weights, plus a dense bool `[Q, C + Q]` oracle. Its first `C` keys represent frozen absolute target-context positions; every query sees only `0..absolute_anchor`, while query keys remain bidirectional within a block and isolated across blocks. The identical predicate can construct a FlexAttention `BlockMask` when an installed PyTorch exposes `create_block_mask`; CPU tests cover tensor values/dtypes/shapes, predicate/oracle parity, context boundary, and block isolation.
- Exponential per-future-position CE weights, `exp(-(k-1)/gamma)`, with paper defaults 16→7, 10→5, and 8→4.
- Lower-bound feature-cache estimator comparing dataset-wide offline storage, online per-batch working set, and a bounded ring buffer. It materializes no features.
- North candidate derivation from local `config.json`, `tokenizer_config.json`, and `tokenizer.json`, including the reference layer-spread formula, target vocab size 262144, and an audited `<MASK_TOKEN>` ID derived consistently from the tokenizer's special-token table and vocabulary.
- Config-fingerprinted, checkpoint-unverified AutoGPTQ teacher manifest recording complete quantization identity, selected zero-based block IDs, and target layer count; exact teacher extraction is intentionally not implemented.
- Dependency-free exact checkpoint identity tooling that incrementally hashes explicitly requested `config.json`, a Hugging Face weight index, and its declared shards without loading tensors. Rocky and Bitey independently established all three verifier identities: AutoGPTQ has 19,882,132,698 bytes/seven shards and manifest SHA-256 `fca065d1f7df51b17763e5555363c36100d72c638cf318f71ef6c7f9b5319cae`; Cohere W4A16 has 19,354,738,299 bytes/four shards and manifest SHA-256 `64ee97e76305fb94c28eb93f0babf91fbb335062b14c5018cf8f86130504a27a`; Cohere FP8 has 32,029,761,935 bytes/seven shards and manifest SHA-256 `35812fdf32f497a558f31bbea43e7d69f8c1cd43c66530c7499de2f293ae2bb6`. Manifests are retained under `configs/`.
- Optional `.[torch]` training-step contract in `north_dflash_training.training`: typed detached clean teacher-state bundles with declared layer ordering, concatenation to `[B, C, L*H]`, direct frozen shared embedding/LM-head references, an architecture-specific draft-adapter boundary, and a weighted CE mean over exactly non-ignored masked future labels. The tiny `SyntheticDraftAdapter` proves only CPU gradient flow/loss reduction; it is not a Qwen3 or North draft.
- A separately isolated, capability-gated `transformers_draft_adapter` runs only the real local `dflash.DFlashDraftModel` with Transformers eager attention. It derives full RoPE positions as clean context `0..C-1` followed by packed absolute query positions, and converts the audited bool `[Q, C + Q]` visibility oracle to the exact additive `[B, 1, Q, C + Q]` mask that Transformers 4.57.1 eager Qwen3 attention adds to its scores. Tiny random Qwen3/DFlash CPU tests prove forward shape, blocked-context/inter-block non-leakage, real-draft-only gradients with frozen shared modules, and a bounded loss smoke. It intentionally has no cache, FlexAttention, non-eager backend, or North integration. Base imports do not require PyTorch or Transformers.
- Synthetic CLI dry-run. It performs no model loading, dataset download, GPU operation, model-file write, shard hash, or server interaction.
- Guarded pre-GPU runtime-probe artifact tooling: config-only selectable smoke/full geometry and deterministic BF16 random `DFlashDraftModel` writer. The default smoke is one full draft layer, one zero-based target block ID `[24]`, and block size 2 while preserving all North runtime dimensions; the 8-layer/5-feature/block-16 candidate requires an explicit full-only acknowledgement. Generation refuses existing outputs, records a random/non-production manifest and the retained source checkpoint identity link without reading target weights, estimates serialized bytes/free space, excludes target embedding/LM-head tensors, and fails closed unless the local vLLM DFlash registry/mapper/sharing/extractor source contract is present. - `feature_stream.py` provides the bounded connector-consumption boundary. It requires a pinned checkpoint manifest/image/backend, rejects prefix caching, validates exact request token IDs plus BF16 `[C, L, H]` shape/order/finiteness, clones one request into detached `[1, C, H]` `TeacherFeatureBundle` states, and applies fail-closed item/token/byte backpressure without silent eviction. Transactional `peekleft`/`ackleft` semantics keep a request active until successful consumption. It never deletes connector artifacts.

## Explicitly missing

- A retained-checkpoint adapter for standardized Speculators checkpoints. The upstream self-contained checkpoint includes verifier vocabulary tensors, so current artifacts are diagnostic/deployment exports rather than compliant draft-only retained checkpoints.
- Continuous server-to-ring orchestration, restart/retry policy, and pilot-scale scheduling. Bounded cumulative phases through 80 request transactions passed storage/resume, but their weights are invalidated by the old inclusive-anchor layout.
- Held-out response-quality and target-only throughput gates. The fixed Magicoder holdout proves acceptance scaling, but it does not score response correctness, compare target-only output parity, or establish production concurrency/long-context throughput. Most training responses were bounded 512-token prefixes rather than completed answers.
- Production deployment qualification. The official five-layer draft serves correctly, but concurrency, long-context memory/throughput, target-only speedup, response quality, and a retained draft-only export still need gates before deployment.
- A full-source vLLM build of `experiment/north-dflash` commit `a1cad4f67`. The passed runtime is an exactly pinned composite: vLLM 0.25.1 plus the Cohere2Moe auxiliary-state overlay and fail-closed probe assertions. Its image ID and relevant installed source hashes are retained with the run rather than misrepresented as a full build of that checkout.

BF16 appears only as a possible initializer in the candidate notes. It is not an alternative deployment target. Each final branch must remain paired to one exact local verifier: AutoGPTQ group-32, Cohere NVFP4 W4A16 group-16/QAD, or Cohere FP8.
